# 인터페이스 초안: 로봇팔이 차를 세우고 출발시키는 방식 (로봇팔 쪽 구현 기준)

작성: 2026-11-10 · 대상: 인터페이스 담당자와 함께 검토할 초안.
기준 문서: 팀 레포 `Team_koo` 의 `docs/interfaces.md` (2026-11-10 휘성·재상 합의), `common_interfaces/msg/CarStatus.msg`, `LoadingStatus.msg`.

이 문서는 **새 토픽이나 메시지를 만들지 않습니다.** 이미 합의된 토픽을 로봇팔이 어떻게 쓰는지 적고,
문서와 구현이 다른 곳 · 아직 정해지지 않은 곳만 "확인할 것" 으로 모았습니다.

## 1. 쓰는 토픽 (바뀐 것 없음)

| 토픽 | 메시지 | 방향 | QoS |
|---|---|---|---|
| `/car/status` | `common_interfaces/msg/CarStatus` | 자동차 → 로봇팔 | RELIABLE, TRANSIENT_LOCAL, depth 1 |
| `/arm/loading_status` | `common_interfaces/msg/LoadingStatus` | 로봇팔 → 자동차 | RELIABLE, TRANSIENT_LOCAL, depth 1 |

로봇팔은 상태가 바뀌면 바로, 안 바뀌어도 **1초마다** 다시 보냅니다. 노드 이름 `arm_loading`. 구현: `mission/load_link.py` 의 `RosLoadLink`.

## 2. 로봇팔이 보내는 상태와 시점

| 상태 | 언제 보내나 | color | attempt |
|---|---|---|---|
| `WAITING` (0) | 전원을 켜 대기 자세에 도착했을 때 / 차가 떠난 뒤 / 추적하던 차를 놓쳤을 때 | `""` | 0 |
| `TRACKING` (1) | 대기 자세에서 YOLO 가 차 위 상자(없으면 차)를 처음 찾았을 때 | `""` | 0 |
| `STOP_REQUEST` (2) | 추적하던 받침(1번 모터)이 **기준 차 위치 각도 − 미리 내는 각도** 에 왔을 때 | `""` | 0 |
| `IN_PROGRESS` (3) | 완전 정차를 확인하고 포스트잇 색을 읽은 뒤, 시도를 시작할 때마다 | `"red"`/`"blue"` | 1~3 |
| `SUCCESS` (4) | 넣은 뒤 YOLO 가 "공이 든 상자" 를 확인했을 때 | 읽은 색 | 마지막 시도 번호 |
| `FAILED` (5) | 3차 시도까지 실패 / 색을 못 읽음 / 정지 신호 뒤 정차 확인 실패 / 과열 등 오류 | 읽은 색 또는 `""` | 마지막 시도 번호 |

## 3. 로봇팔 안에서 일어나는 일

1. **대기**: 대기 자세(`watch`)에서 그리퍼 카메라 + YOLO(`arm_v1_yolo11n`)로 상자 · 차를 찾습니다.
2. **추적**: 찾으면 받침(1번 모터)만 조금씩 돌려 대상을 화면 가운데에 둡니다 (`TRACKING`).
3. **정지 신호**: 받침이 미리 저장한 "기준 차 위치" 각도에 가까워지면 `STOP_REQUEST`.
4. **완전 정차 확인**: 정지 신호 뒤에도 **계속 추적**합니다. 상자가 화면에서 12픽셀 넘게 움직이지 않고 받침도 돌지 않은 채
   **1.5초**(설정 1~2초)가 지나면 완전 정차로 봅니다. 그 순간의 받침 각도를 임시로 기억합니다.
5. **색**: 포스트잇을 15장 보고 다수결로 빨강/파랑을 정합니다.
6. **집기 · 넣기**: 티칭한 `빨간공_집기` 또는 `파란공_집기` → `바구니_넣기` (기억한 각도와 기준 각도의 차이만큼 받침을 더 돌려 재생).
7. **확인**: "공이 든 상자" 가 3초 안에 3번 이상 보이면 `SUCCESS`. 아니면 다음 시도 (최대 3회).
8. **복귀**: 대기 자세로 돌아가, 자동차의 `DRIVING` 을 받거나 상자가 3초 동안 안 보이면 `WAITING`.

## 4. 합의 문서와 다른 곳 → 확인할 것

| # | 합의 문서 | 로봇팔 구현 | 제안 |
|---|---|---|---|
| 1 | `STOP_REQUEST` 는 "1번 모터가 **정중앙(정면)** 에 오면" | "**기준 차 위치 각도**" 에 오면. 이 각도는 `바구니_넣기` 를 티칭할 때 차가 서 있던 방향을 저장한 값 | 문서를 "로봇팔이 티칭한 기준 각도" 로 고치기. 정면에 차를 세우고 티칭하면 결과는 같습니다 |
| 2 | 정지 확인은 "`AT_LOADING_ZONE` **또는** 상자가 안 움직임" | **카메라로 1.5초 동안 안 움직임을 반드시 확인.** `AT_LOADING_ZONE` 은 기록만 하고 조건으로 쓰지 않음 | 이대로 두기 (메시지가 먼저 와도 차가 미끄러지는 중일 수 있어서) |
| 3 | 정지 신호 뒤 차가 안 서는 경우는 적혀 있지 않음 | 15초 안에 정차를 확인하지 못하면 `FAILED` 를 보내 차를 보냄 | 예외 처리 표에 한 줄 추가 |
| 4 | 색을 못 읽는 경우는 적혀 있지 않음 | 포스트잇이 3장 미만으로 보이면 추측하지 않고 `FAILED` (다른 색을 넣으면 −20, 실패는 −30) | 팀에서 "추측해서 넣기" 와 "포기" 중 선택 필요 |
| 5 | 차가 먼저 떠나면(`DRIVING`) 동작을 멈추고 `FAILED` | `AT_LOADING_ZONE` 을 한 번이라도 받은 뒤의 `DRIVING` 만 "먼저 떠남" 으로 봄. 동작의 지점과 지점 사이에서 확인 | 자동차가 정지하면 `AT_LOADING_ZONE` 을 **반드시** 보내 주기 (안 보내면 이 보호가 동작하지 않음) |
| 6 | 실패 후 재시도 조건은 적혀 있지 않음 | 다음 시도 전 5초 대기 (떨어진 공을 팀원이 받침대에 다시 놓는 시간). 공이 실제로 돌아왔는지는 확인하지 않음 | 대기 시간을 팀에서 정하기 |

## 5. 자동차 담당에게 부탁할 것

- `STOP_REQUEST` · `IN_PROGRESS` 를 받으면 즉시 정지하고, 멈춘 뒤 `AT_LOADING_ZONE` 을 보내 주세요.
- `TRACKING` 을 받으면 감속해 주세요. 받침은 느리게 돌기 때문에(초당 약 10도) 차가 빠르면 놓칩니다. **적당한 속도는 실물에서 같이 재야 합니다.**
- 정지 신호를 받고 실제로 설 때까지 밀리는 거리를 알려 주세요. 로봇팔의 "미리 내는 각도"(기본 2도)를 그에 맞춥니다.
- `SUCCESS` · `FAILED` 를 받고 출발하면 `DRIVING` 을 보내 주세요.

## 6. 아직 확인하지 못한 것

- ROS2 실제 통신: 이 PC 에는 ROS2 가 없어 `RosLoadLink` 는 한 번도 실행해 보지 못했습니다. 로봇팔 Pi 의 Docker 에서 `common_interfaces` 를 빌드한 뒤 확인해야 합니다.
- 받침만 돌리는 보정은 **좌우(받침을 중심으로 도는 방향)** 어긋남만 맞춥니다. 차가 앞뒤(팔에서 멀어지거나 가까워지는 쪽)로 어긋나면 맞추지 못합니다.
- YOLO 모델을 실제 카메라 사진으로 시험하지 못했습니다 (속도 · 정확도 모두 Pi 에서 측정 필요).
