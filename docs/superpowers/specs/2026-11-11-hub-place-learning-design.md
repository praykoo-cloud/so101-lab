# 허브 수정 + 바구니 넣기 학습 설계 (2026-11-11)

사용자와 대화로 정한 내용. 코드: `mission/place_learn.py` (저장), `mission/place_flow.py` (단계 실행), `mission/place_page.py` (4번 화면), `mission/hub.py`, `mission/loading.py`.

## 1. 허브 메뉴
`1 대기 자세 저장 · 2 카메라·YOLO 확인 · 3 동작 티칭 · 4 바구니 넣기 학습 · 5 상차 미션 실행 · 6 설정 값`
- 예전 4번 "차 추적 테스트" 삭제 (메뉴 · 화면 · /api/track 주소).
- 모든 허브 화면 오른쪽 아래에 **YOLO 인식 카메라** 작은 창 (`/img/live.jpg`, 누르면 크게). 카메라가 없으면 이유를 글로.
- 허브는 Pi 의 Docker 안에서 실행 (`허브_도커.sh`) → 진짜 ROS2 정차 · 출발 신호.

## 2. 4번 바구니 넣기 학습 — 저장 (data/place_learn.json + data/place_learn/<세트>/)
- **세트**(이름, ★ 실행용 하나) = 대기 자세 1개(처음 한 번, YOLO 캡처 + 모터 값) + 여러 **회차**.
- **회차**(이름, ✔ 사용 / ✘ 제외) = 5 바구니 위 · 6 바구니 안 · 7 집게 해제 · 8 성공 확인, 각 순간 YOLO 캡처 1장 + 모터 값(관절 1~5 + 그리퍼 %) + 찾은 바구니 상자. 8 에서 YOLO 성공 판정도 저장.
- 회차는 5→6→7→8 을 다 하고 [다음 단계 진행]을 눌렀을 때 한 번에 저장. 중간에 멈추면 저장 안 함.
- 이름 바꾸기 · 지우기(백업 후) · 사진/값 보기 · [그 자세로 이동] 언제든.

## 3. 한 회차 학습 순서
| 단계 | 하는 일 | 누가 |
|---|---|---|
| 1 | [학습 시작] | 사람 |
| 2 | 대기 자세(poses.json `watch`)로 가서 차를 기다림. 세트에 대기 자세 기록이 없으면 이때 저장 | 프로그램 |
| 3 | 차와 상자가 연속 N장(설정 `load_see_frames`) 함께 보이면 STOP_REQUEST, 상자가 `load_stop_confirm_seconds` 동안 안 움직이면 완전 정차 | 프로그램 |
| 4 | 포스트잇 색 다수결 → IN_PROGRESS(색, 시도) → 3번 동작 티칭의 그 색 공 집기 재생 | 프로그램 |
| 5~7 | 팔(1~5번)만 힘을 빼고(집게는 힘 유지) 손으로 옮겨 [5 저장] [6 저장]. 7 은 [팔 고정] 후 집게를 조금씩 열어 [7 저장] | 사람 |
| 8 | 성공 확인 자세로 옮겨 [8 저장] → YOLO 판정 표시 → **[다음 단계 진행]** (판정은 바꿀 수 있음) | 사람 |
| 9 | 성공: 대기 자세 → SUCCESS(출발) | 프로그램 |
| 10 | 실패: 사람이 공을 받침대에 놓고 [공 놓았어요] → 4번부터. 3번째 실패면 대기 자세 → FAILED(출발) | 프로그램/사람 |

## 4. 테스트 (4번 화면)
세트 · 시작 단계(2~8) 고르기 → 그 단계부터 끝까지 자동. "한 단계씩 멈추기" 선택 가능. 5 이후에서 시작하면 공을 쥐고 있는지 확인하고, 색은 화면에서 고른다. 단계마다 ✅/❌ 와 이유.

## 5. 자동 넣기 (테스트 · 실행 공통, (나) 실시간 맞추기)
- 학습 값 = ✔ 사용 회차들의 평균: 5 자세, 5 에서 본 바구니 가운데 (cx, cy), 6·7·8 자세, 7 그리퍼 %.
- 5: 평균 5 자세로 간 뒤 YOLO 상자가 학습한 (cx, cy) 에 오도록 받침(1번)을 가로 오차로, (설정 시) 어깨(2번)를 세로 오차로 조금씩 움직임. 허용 폭 안이면 끝. 최대 보정 각도 · 시간을 넘으면 실패.
- 6·7: 보정한 만큼(관절별 차이)을 평균 6·7 자세에 더해 이동, 7 에서 학습한 % 만큼 집게를 엶. 8: 받침 보정만 더해 이동 → 성공 확인.

## 6. 상차 미션 실행 (mission/loading.py)
- 켜면 차의 첫 `/car/status` 를 기다렸다가 대기 자세로 (`load_wait_car_power`, `--no-ros` 에서는 건너뜀).
- 기본은 3 의 "보이면 바로 정지" 방식 (`load_use_tracking` 를 켜면 예전 추적 방식).
- 넣기는 4번 ★ 세트로 5 의 자동 넣기. 실패하면 `load_retry_wait_seconds` 기다린 뒤 4(공 집기)부터, 3번째 실패면 대기 자세 → FAILED.

## 7. 위험
- Docker 의 OpenCV(4.5)가 YOLO11 ONNX 를 못 읽을 수 있음 → Pi 에서 먼저 확인.
- `common_interfaces` 가 Docker `.ws` 에 빌드돼 있어야 신호가 나감.
